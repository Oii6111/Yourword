# 悦读词 / Yourword

一个中文界面的个人单词学习网页：导入 TXT 词库，拆分独立词义，让语言模型将目标词义编进英文文章。阅读中标记不认识的词义，之后只复习仍不认识的部分。

## 本机启动

需要 Node.js 20.19+ 或 22.12+，以及 npm。

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:5173/`。开发与预览均固定使用 5173，端口被占用时明确报错，不再自动切换。先关闭旧的开发或预览进程再启动。应用基于 React、TypeScript 和 Vite，附带 Node.js 本机后端，无需账号。一个命令同时启动页面、文件存储和模型代理接口。

后端配置持久化到项目的 `data/settings.json`，关闭浏览器、重启应用后仍可使用，同一台电脑的不同浏览器读取同一份 API 配置。首次打开新版会将已有浏览器 API 配置迁到后端；只有保存成功后才删除旧浏览器配置，已有后端配置优先。没有旧配置时，在「连接设置」填写并保存一次即可。

词库、筛选记录、分支、阅读设置、文章历史、队列和下一篇缓存统一保存在 `data/libraries.json`；导入草稿保存在 `data/import-draft.json`。浏览器只是界面，跨浏览器和端口均读取同一目录。文件通过临时文件原子替换，并保留上一份 `.bak`；版本冲突会拒绝覆盖并提示刷新，文件损坏会明确报错并保留原文。备份时复制整个 `data/` 目录。

首次打开新版只读读取当前地址下的旧 IndexedDB 并迁移到后端，保留浏览器原数据和 `data/migrations/` 下的来源快照。同一地址的同一份快照只迁移一次；与后端同编号但内容不同的词库保留为迁移副本，不覆盖新进度。如果旧词库在 5174：在同一个浏览器运行 `npm run dev -- --port 5174`，打开 `http://127.0.0.1:5174/` 完成一次迁移，再关闭该服务并回到默认 5173。迁移完成后应用不再提供浏览器数据导入导出入口；迁移失败时编辑操作暂停，原数据保留，检查服务后刷新重试。

生产构建后运行 `npm start` 或 `npm run preview`，也会启动本机后端。后端只接受本机应用的同源请求，是个人自用模式；API 配置文件不会放进前端构建产物，开发服务器也禁止通过文件网址下载配置目录。可用 `CONTEXT_WORDS_DATA_DIR` 指定其他配置目录。

## 词库导入与管理

TXT 每行是「单词 + 一个真实 Tab 字符 + 中文释义」，不是多个空格，也不是字面上的 `\t`。以下示例的单词与释义之间是实际 Tab：

```text
bank	n. 银行；岸
revolt	n. 反抗；造反，起义 v. 起义；反抗
curious	adj. 好奇的
```

支持 UTF-8、GB18030 / GBK，默认自动识别，也可手动选择编码。可以选择 TXT 文件或粘贴内容；原始内容、错误行和去重数量都在词库页显示。

JSON 词库可通过 `node scripts/convert-vocabulary.mjs "输入.json" "输出.txt"` 转换。支持包含「单词」「释义」字段的词条数组，或以词库名称为键的词条数组集合。输出为 UTF-8，每行 `单词<Tab>中文释义`，逐条保留原有顺序、大小写与释义，不添加「其他拼写」字段，也不推测词性。省略输出路径时在 JSON 旁生成同名 TXT，已有文件不会覆盖。

1. 在「词库」选择文件或粘贴内容，并填写词库名称。程序在本机按词性识别多条义项。同词不同词性，以及分行填写的不同释义，会保留为独立对象。
2. 检查预览，可修改、合并相同单词与词性的义项，或删除义项。如果词库已分好义项，直接使用当前预览；「智能拆分词义」是可选操作，会让模型合并同义解释、拆分不同含义，严格依据输入释义。
3. 点击「保存词库」。保存不调用模型，不生成文章；每次导入单独保留，不覆盖其他词库及其学习记录。
4. 在已保存词库列表中，可以改名、查看义项、导出 TXT 或删除词库。删除需要确认，会同时删除这份词库的学习进度与文章历史。

### 快速筛词与生词分支

导入预览确认后，可以点「保存并快速筛词」；已保存的词库也可随时点「快速筛词」。筛词页保留米白、草绿色系，单词按整齐的列排列，每列从上往下阅读，再移到右侧下一列；列间有细分隔线，控制面板固定在左上方。同一单词只出现一次，不按词义拆成多个标记项。点击标记整个单词不认识，再次点击取消，生词用颜色区分。默认隐藏中文释义，右键或点词旁的问号可查看该词的全部导入释义，也可开启「显示中文释义」。搜索可匹配单词、词性及任一释义，「只看已标记」方便核对，「刷新布局」可打乱顺序。筛词标记自动保存，刷新后可继续。

筛词采用固定分页，默认每页 300 个单词，可选择 50、100、200 或 300 个。通过「上一页」「下一页」或「跳转页码」切换，翻页替换当前页内容并保留所有已标记单词，不会不断追加词条。搜索、筛选和改变每页数量都会回到第一页。

每页可以选择「正选：标记不认识」或「反选：标记认识」。正选点击生词，自动保存；反选只点击本页认识的词，然后点「保存本页筛选」，将本页未选中的词加入生词，并移除本页认识的词。其他页的已保存标记保持不变，尚未筛选的页不会自动加入生词。切换模式不改变已保存结果；反选可点「放弃本页筛选」取消，未提交的反选在离开筛词页后舍弃。存在未保存反选时，需要先保存或放弃后再创建分支。

点击「创建生词分支词库」会将已标记单词的全部导入词义保存为一份独立词库，名称包含创建时间，列表显示来源及时间，同一来源的新分支优先显示。旧版本只标记某个词义的记录也会按该单词选中，创建分支时包含其全部导入词义。每次创建保留一份快照；分支可继续筛词，也可在「阅读」中选择，生成仅覆盖该分支词义的文章。筛词以单词为单位，阅读学习仍保留独立词义。原词库和各分支的阅读进度相互独立，删除原词库后，已创建的分支仍可使用。未标记的单词不自动计为已掌握。

## 阅读与复习

1. 在「连接设置」填写 Base URL、API Key 和模型名，测试并保存。API 设置保存在本机后端。
2. 到「阅读」选择已保存词库，设置「每篇覆盖词义数量」和「预期长度（英文词）」。默认每篇最多 20 个独立词义，预期长度为 400 词；可设置 1–50 个词义，预期长度填写正整数。数量按词义计算，同词不同义分别学习，同篇可能因为剩余数量或义项分散而少于上限。旧版的长度上限设置会自动迁为预期长度。
3. 开始该词库的第一篇阅读材料。首次覆盖队列随机排序并保存，从尚未覆盖的义项中选词；同词不同义优先分到不同批次。模型先按词义关系、常见搭配及自然场景分组，自主决定生成多少篇短文、段落或句组。相关词尽量组成较完整的连贯段落，无关词分开写，不强制共同主题或同一个故事。生成并验证成功后进入独立阅读页面 `#/read`。
4. 点击词语显示本句中文释义并自动标记不认识，再次点击取消；键盘聚焦后按回车也可操作，悬浮或聚焦本身不会打开卡片。同一词义的多处出现共享标记，同词不同义分别记录。手机轻点后显示底部词义卡片，卡片和生词标签也可取消标记。普通非目标词点击后调用模型查当前语境的含义并加入复习，取消标记后恢复普通词样式；只有本篇目标词显示绿色下划线。
5. 阅读当前篇时，应用自动生成同一轮的下一篇，并保存为缓存。预生成不提交当前标记，也不推进覆盖进度。点击「读完，下一篇」先保存当前标记，再打开已准备的文章；未准备好时继续等待或生成。缓存保存在后端文件，刷新后可复用。
6. 完成首次全部覆盖后，用期间累计的不认识词义开始复习。每轮重新记录标记，下一轮只使用上一轮仍不认识的词义；集合为空时完成学习。每轮最后一篇读完并提交标记后，才能确定下一轮的词义集合，因此不会提前生成下一轮。

文章页显示当前轮次（首次覆盖为第 0 轮）、本轮需覆盖总量、已覆盖量、待覆盖量、本篇词义数与实际英文词数。目标词轻微加下划线；为写出自然英文，文章仍可使用其他正常词汇。

提示词优先要求逻辑自洽、自然易懂及正确词义，不再追求最少总词数，也不限制为一篇文章。每个独立片段自行交代人物和场景，段内时间、指代和因果须合理；相关词尽量写成较长的连贯段落，难以组合的词可以独立造句。独立片段用空行分隔，模型自行决定片段数量及篇幅。预期长度仅作参考，允许为完整语境写得更长，不靠重复内容凑字数。程序统计实际词数，但不按总长度拒绝或修复文章。词形、注解位置和目标词义覆盖仍需通过，出现序号按全部阅读材料统一计数。独立语境审核按各片段判断，不要求片段之间情节相关；接受同义表达和正常语法变化，每个词义有一处正确使用即可。轻微生硬、含糊或模型不确定时仅保存提示并允许阅读，即使该词义只有提示也不触发修复。明确错义、词性明显错误或审核结构无效时最多修复一次，仍失败则保留进度并提示重试。提示保存在文章中，当前阅读与历史回顾均可查看。

阅读页保留已生成的文章历史，记录各篇的轮次及覆盖数量。历史回顾只读，显示当时的生词标记，不会改变当前学习进度。刷新可恢复当前阅读、标记和缓存；重新开始该词库会重新随机排序，并保留原来的文章历史。不同词库分别保存设置、队列和学习记录。

## 词义整理中断与恢复

只有主动点击「智能拆分词义」才会调用模型整理。每批最多 20 条释义，每批成功词条立即保存；个别词条校验失败时，只重试问题词条一次。仍失败的保留原始释义、标为“待确认”，其余批次继续处理。

整理完成后，可以点“只看待确认”查看问题词条，直接修改释义，或用分号隔开不同含义后点“按分号拆分”。逐项点“确认词义”，再保存词库；不会静默采纳模型改写、新增或遗漏的释义。

网络、鉴权错误或取消会暂停模型调用。导入草稿与完成进度独立保存在本机后端文件，保留现有学习记录；刷新后回到词库页，点“继续拆分剩余词条”即可续接，已完成部分不会重复请求。

如果希望直接使用已识别的词义，在暂停或待确认状态下点「跳过 AI 拆分，使用当前词义」。这会保留当前预览，包括已完成的拆分结果和未处理的原释义，解除拆分与待确认门槛，不再请求剩余词条。检查并编辑当前预览后，可直接保存词库；刷新后仍可继续使用当前词义。

本机保存失败会明确提示，请保持页面开启并重试。重新导入文件或修改原始 TXT 内容表示开始新的整理任务，会重置该导入的拆分进度，已保存词库保持不变。旧版本在报错前未保存的整理结果无法追溯恢复。

## API 与本机数据

使用兼容 OpenAI Chat Completions 的接口，Base URL 示例为 `https://api.openai.com/v1`。模型需能遵循提示词输出 JSON；不要求服务支持 `json_schema`。文章生成、词义语境验证、主动查义和可选 AI 拆义会产生模型请求；本地导入与预览不调用模型。

后端对 DeepSeek 模型或 `deepseek.com` 服务发送 `thinking: { type: 'enabled' }`，开启模型思考；文章创作、修复和独立词义审核均使用该模式。其他兼容服务不发送此专用参数。服务明确拒绝该参数时，应用提示接口不支持开启思考，需使用支持该参数的 DeepSeek 接口或调整模型。独立词义审核仍会单独调用模型，必要时最多修复一次。

浏览器调用同源 `/api/chat/completions`，本机后端读取已保存配置并转发到模型服务，模型服务无需允许浏览器跨域（CORS）。测试连接通过 `/api/settings/test` 使用当前输入，测试不会自动保存修改。应用区分鉴权、模型、响应格式、超时与网络错误。取消生成时会同时中断后端对模型的等待。真实 API 的可用性取决于你填写的服务、Key 和模型。

每次模型请求最多等待 150 秒，包括等待与接收完整响应内容；前端与后端都支持超时和取消。当前接口为非流式请求，文章创作、独立词义验证和修复分别计时。日志中的 HTTP 状态来自本机代理，成功返回需等待模型完整响应。

「连接设置 → 最近模型请求日志」保存最近 30 次请求的阶段、开始时间、耗时、模型、服务域名、目标数量、HTTP 状态和错误类型，刷新后仍可查看。日志不保存 API Key、词库、提示词、文章或服务错误原文，可单独清空。页面刷新前尚未结束的请求会标为中断；浏览器存储不可用时，日志仅留在当前页面内存中。旧版本未记录的请求无法追溯；服务内部排队或模型生成耗时需要结合提供商日志确认。

多份词库及学习记录与 API 配置都保存在本机后端的 `data/`，浏览器不再写入新的 IndexedDB 学习数据或读取已保存的 Key。界面显示“已保存在后端”，Key 留空时沿用原值；更换服务地址时必须重新填写 Key。配置文件包含明文 Key，`data/` 已加入 Git 忽略，备份时按私密文件处理。迁移成功后清除浏览器数据不会删除后端学习记录；迁移前请保留浏览器原数据。

生成期间可取消。文章需通过原文位置、词形、目标 ID 与模型词义验证，失败会尝试修复一次；再次失败时可以重试，原文章、队列和标记保持。模型对释义和语境的判断仍可能出错，请检查导入预览，并按实际语境判断。

## 验证与构建

```powershell
npm test
npm run test:server
npm run build
npm run preview
```

单元测试覆盖词库解析与编码、多词库迁移与保存、学习队列、分词位置、预期长度提示与不限实际篇幅、配置迁移与模拟 API 成功/失败。后端测试使用临时目录和模拟模型服务，覆盖配置重启恢复、Key 不回显、同源检查、更换服务需新 Key、鉴权代理、超时、取消和开启 DeepSeek 思考。真实 API 连接需要使用你的配置在设置页测试。

浏览器验收测试使用模拟 API，覆盖词库保存与阅读选择、暂停拆分后跳过、多义词隔离、普通词查义、生成失败保留标记、刷新恢复、复习集合收敛和手机布局：

```powershell
npx playwright install chromium
npm run test:e2e
```

如果已有 Chromium，可以通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 环境变量指定其可执行文件路径。模拟接口验收不产生真实模型调用；实际耗时与服务、网络、目标数量以及是否触发修复有关。
